# decaf

A lightweight Java Language Server built in Go, inspired by [Scala Metals](https://scalameta.org/metals/). 

decaf acts as a **thin client** — it handles LSP communication with your editor, while delegating compilation to [Bloop](https://scalacenter.github.io/bloop/) (Build Server Protocol). Semantic information (goto definition, find references) is powered by [SemanticDB](https://scalameta.org/docs/semanticdb/guide.html) files generated by the `semanticdb-javac` compiler plugin.

## Architecture

```
Editor (Neovim/Zed)
    │  LSP (JSON-RPC over stdin/stdout)
    ▼
  decaf
    │  BSP (JSON-RPC over stdin/stdout)
    ▼
  Bloop ──► javac + semanticdb-javac ──► .semanticdb files
                                              │
                                              ▼
                                        SemanticDB Index
```

## Features

- **Diagnostics**: Compilation errors/warnings forwarded from Bloop in real-time
- **Goto Definition**: Jump to symbol definitions via SemanticDB index
- **Find References**: Find all usages of a symbol via SemanticDB index
- **Compile on Save**: Automatic incremental compilation when files are saved

## Prerequisites

- **Go 1.21+** (to build decaf)
- **Bloop** — install via [coursier](https://get-coursier.io/):
  ```sh
  cs install bloop
  ```
- **Maven** (for Maven projects)

> **Note:** You do **not** need to manually configure `semanticdb-javac` or run `bloopInstall`. decaf handles all of this automatically on startup.

## Build

```sh
git clone https://github.com/fwrq41251/decaf.git
cd decaf
go build -o decaf ./cmd/decaf
```

## Usage

Just open your Maven project in an editor configured with decaf. On first startup, decaf will automatically:

1. **Detect `pom.xml`** in your workspace
2. **Run `mvn bloopInstall`** to export project config to `.bloop/`
3. **Download `semanticdb-javac`** from Maven Central (cached in `~/.cache/decaf/`)
4. **Inject it into `.bloop/*.json`** configs (adds `-Xplugin:semanticdb`)
5. **Connect to Bloop**, compile, and index `.semanticdb` files

After the initial setup, subsequent startups skip steps 2-4 (already configured) and go straight to compilation.

## Editor Setup

### Neovim

Using `nvim-lspconfig`, add to your config:

```lua
vim.api.nvim_create_autocmd('FileType', {
  pattern = 'java',
  callback = function()
    vim.lsp.start({
      name = 'decaf',
      cmd = { '/path/to/decaf' },
      root_dir = vim.fs.root(0, { '.bloop', 'pom.xml', 'build.gradle' }),
    })
  end,
})
```

### Zed

Add to your Zed settings (`settings.json`):

```json
{
  "lsp": {
    "decaf": {
      "binary": {
        "path": "/path/to/decaf"
      }
    }
  },
  "languages": {
    "Java": {
      "language_servers": ["decaf"]
    }
  }
}
```

## Logging

decaf writes logs to `decaf.log` in the working directory. Check this file for debugging:

```sh
tail -f decaf.log
```

## How It Works

When you save a file:

```
didSave → Bloop compile (with semanticdb-javac) → .semanticdb generated → Index updated
```

When you request "Go to Definition":

```
Cursor position → Find symbol in SemanticDB index → Return definition location
```

decaf never parses Java source code directly. All semantic information comes from the `.semanticdb` files produced by the `semanticdb-javac` compiler plugin during Bloop compilation.

## Project Structure

```
decaf/
├── cmd/decaf/main.go              # Entry point
├── proto/semanticdb.proto         # SemanticDB protobuf schema
├── internal/
│   ├── jsonrpc/                   # JSON-RPC transport + dispatcher
│   ├── lsp/                       # LSP protocol handlers + types
│   ├── bsp/                       # BSP client (Bloop connection)
│   ├── index/                     # SemanticDB index (definition/references)
│   ├── semanticdb/                # Generated protobuf Go code
│   └── server/                    # Server orchestration
└── go.mod
```
