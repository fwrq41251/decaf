# decaf: Java Language Server

`decaf` is a lightweight Java Language Server (LSP) built in Go, inspired by Scala Metals. It acts as a thin client that handles LSP communication with editors and delegates heavy-duty compilation to [Bloop](https://scalacenter.github.io/bloop/) via the Build Server Protocol (BSP). Semantic information (definitions, references, hover) is powered by [SemanticDB](https://scalameta.org/docs/semanticdb/guide.html).

## Project Overview

- **Main Technologies:** Go (1.25.0+), LSP, BSP, SemanticDB, Protocol Buffers.
- **Architecture:** 
  - **LSP Layer:** Handles communication with editors (e.g., Neovim, Zed) over JSON-RPC (stdin/stdout).
  - **BSP Client:** Communicates with Bloop to trigger compilations and receive diagnostics.
  - **SemanticDB Indexer:** Parses `.semanticdb` files generated by the `semanticdb-javac` compiler plugin to provide jump-to-definition and find-references capabilities.
  - **Setup Logic:** Automatically configures Maven/Gradle/Bloop and injects the SemanticDB plugin.

## Key Directories

- `cmd/decaf/`: Contains the main entry point for the LSP server.
- `internal/lsp/`: Implements the Language Server Protocol (LSP) handlers.
- `internal/bsp/`: Implements the Build Server Protocol (BSP) client for Bloop integration.
- `internal/server/`: Orchestrates the server lifecycle and dispatching.
- `internal/index/`: Manages the SemanticDB-based symbol index.
- `internal/setup/`: Handles project discovery, Bloop installation, and SemanticDB plugin injection.
- `internal/jsonrpc/`: Low-level JSON-RPC transport and dispatcher.
- `proto/`: Contains the `semanticdb.proto` definition.

## Building and Running

### Build
To build the `decaf` binary:
```sh
go build -o decaf ./cmd/decaf
```

### Run
The server communicates via stdin/stdout. It writes logs to `decaf.log` in the current working directory.
```sh
./decaf
```

### Testing
To run all tests in the project:
```sh
go test ./...
```

## Development Conventions

- **Logging:** All logs must be written to the provided `*log.Logger` in the `server` or `handler`, which redirects to `decaf.log`. Never use `fmt.Println` for server-side logic as it interferes with the JSON-RPC stream.
- **Protocol:** Rigorously follow the LSP and BSP specifications.
- **Error Handling:** Errors in handlers should be logged and returned as JSON-RPC error responses where appropriate.
- **Concurrency:** The server uses a dispatcher to handle concurrent requests. Ensure thread-safety in shared components like the index.
- **Dependencies:** Avoid adding heavy external dependencies. Currently relies on standard library and `google.golang.org/protobuf`.

## Setup Flow

When `decaf` starts in a project directory (e.g., a Maven project):
1. Detects `pom.xml` or `build.gradle`/`build.gradle.kts`.
2. Runs `mvn bloopInstall` or `gradle bloopInstall` (if needed) to create `.bloop/` configuration.
3. Injects the `semanticdb-javac` plugin into Bloop JSON configs.
4. Connects to Bloop via BSP.
5. Indexes any existing or newly generated `.semanticdb` files.
